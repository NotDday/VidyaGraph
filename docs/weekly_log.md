## Week 1 — Foundation & Database

**Date:** 2026-06-08  
**Tag:** `week-1-complete`

### What Was Built

1. **Repository structure** — Full directory layout with all files initialised.
2. **Database schema** (`schema/schema.sql`) — Three tables, six indexes, materialized view with auto-refresh trigger, recursive CTE view with cycle detection.
3. **Seed test data** (`schema/seed_test.sql`) — Two synthetic documents, six chunks, five edges with verification queries.
4. **WSL backend skeleton** (`wsl_backend/wsl_server.py`) — DB connection with exponential backoff, wire protocol helpers, insert/query listeners, DB writer thread.
5. **Documentation** — README, architecture.md, .gitignore, requirements files.

### What Was Tested

- Schema SQL syntactic validity and constraint correctness.
- Wire protocol helpers implement exact 4-byte big-endian framing.
- Seed data creates correct number of documents, nodes, and edges.

### Deviations from Spec

| Deviation | Justification |
|---|---|
| TCP ports: 5432/5433 → 5555/5556 | Port 5432 is already used by ShaktiDB. |
| `imported_at_proxy` → `dr.imported_at` | Column didn't exist in `content_nodes`; fixed to use join. |
| Trigger is non-deferred | PostgreSQL doesn't support `DEFERRABLE` on statement-level triggers. |

## Week 2 — TCP Pipeline & Embedding Engine

**Date:** 2026-06-08  
**Tag:** `week-2-complete`

### What Was Built

1. **Complete WSL server** — Full handler thread (receive, validate, enqueue), DB writer with `execute_values` bulk insert for all three tables, proper rollback on errors, SIGTERM handling with queue draining.
2. **Windows backend** — FastAPI app with all endpoints, `SentenceTransformer` model loading on CUDA at startup, `chunk_text()` (300-word chunks, 50-word overlap, provenance tracking), `batch_embed()` (batch_size=32, unit normalisation, timing logs), `build_semantic_edges()` (pairwise cosine, threshold 0.4).
3. **TCP socket client** — Persistent connection class with exponential backoff reconnect.
4. **`POST /upload` endpoint** — Full pipeline: read → chunk → embed → edges → stream to WSL. Returns detailed timing breakdown.

### What Was Tested

- Chunking produces correct number of chunks with proper overlap.
- Embedding output shape is (N, 384) with unit-normalised vectors.
- Wire protocol round-trip integrity via loopback socket tests.

### Deviations from Spec

| Deviation | Justification |
|---|---|
| Added CUDA → CPU fallback | If CUDA is unavailable, model loads on CPU instead of crashing. |
| Node IDs generated by DB, not client | DB-generated UUIDs via `RETURNING` are more reliable than client-side IDs. |

## Week 3 — Query Engine & Cross-Document Intelligence

**Date:** 2026-06-08  
**Tag:** `week-3-complete`

### What Was Built

1. **Query TCP server** (port 5556) — Full handler dispatching three query types: search (recursive CTE), fetch_embeddings (for cross-doc), summarise (node text concatenation).
2. **`build_cross_document_edges()`** — Compares new chunk embeddings against all existing chunks, emits edges where cosine > 0.5. Detailed docstring explaining academic significance.
3. **`/search` SSE endpoint** — Full streaming implementation with 40ms node pace and 20ms edge pace.
4. **`/graph` endpoint** — Returns full graph from knowledge_summary + knowledge_edges.
5. **`/status` endpoint** — Returns live socket connection status for both channels.
6. **`POST /summarise` endpoint** — Added (not in original 5-endpoint table but referenced in UI spec).

### What Was Tested

- Recursive CTE parameterised query against ShaktiDB (parameterised, not string-formatted).
- Cross-document edge building verified with known embedding matrices.
- SSE event stream format validated (data: JSON\n\n).

### Deviations from Spec

| Deviation | Justification |
|---|---|
| Added `/summarise` as 6th endpoint | Required by the lasso selection UI but not listed in the endpoint table. |
| Full graph uses top_k=1000 (not unlimited) | Prevents unbounded queries on large databases. |

## Week 4 — Frontend: Graph Canvas & Core UI

**Date:** 2026-06-08  
**Tag:** `week-4-complete`

### What Was Built

1. **`index.html`** — Full dark-mode dashboard with three-panel layout. Tailwind CSS v3 CDN, Inter + JetBrains Mono fonts, glassmorphism panels, custom CSS animations (pulse, shimmer, fade-in-scale).
2. **`app.js`** — Complete Vis.js Network integration:
   - ForceAtlas2-based physics with organic clustering
   - `buildVisNode()` with centrality-based coloring (purple/teal/coral)
   - `buildVisEdge()` with relationship-type styling (solid/dashed)
   - Drag-and-drop upload with progress bar
   - SSE search with progressive node reveal
   - Node click → right drawer with raw text, provenance, connections, "Find Similar" button
   - Timeline slider filtering by imported_at timestamp
   - Shift+click multi-select (lasso) with summarise modal
   - Socket status badge polling every 3 seconds
   - Toast notifications for upload results/errors

### What Was Tested

- Graph renders correctly with seed test data.
- Upload flow triggers progress bar and refreshes graph.
- Drawer opens on node click and displays correct metadata.
- Status badge reflects three states (connected/reconnecting/disconnected).

### Deviations from Spec

| Deviation | Justification |
|---|---|
| Vis.js `multiselect: true` instead of lasso API | Vis.js doesn't have a built-in lasso tool; Shift+click multi-select achieves the same functionality. |
| Added toast notification system | Provides user feedback for upload results and errors — better UX than silent operations. |
